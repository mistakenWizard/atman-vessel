# Post-Mortem: `orch init` Schema Mismatch & Idempotency Blocker

## 1. Incident Overview
On May 20, 2026, a critical technical blocker was identified where the `orch` tool (AtmanVessel) was unable to resume tasks after initialization. The system reported a `missing field version` error during `orch task start`, preventing all agentic collaboration.

## 2. Root Cause Analysis
- **Missing Field**: The `Profile` struct in the Rust core expected a `version` field that was not being scaffolded by the `init` command, nor was it present in the legacy `session.json`.
- **Parser Strictness**: `serde_json` was configured (by default) to fail if a required field was missing, and no fallback defaults were provided for critical structs.
- **Idempotency Failure**: The `Session::save` method enforced a strict version check (`disk version > memory version`). Running `orch init` on an existing directory produced a session with `version: 1`, while the in-memory object had `version: 0`, leading to a permanent "Version mismatch" error that blocked re-initialization.

## 3. Resolution
- **Schema Hardening**: 
    - Added `version` field to `Profile`.
    - Implemented `#[serde(default)]` and custom default providers across `Session`, `SessionState`, `Profile`, and `Provenance`.
    - Added `signature` and `classification` fallbacks to `Provenance`.
- **Command Idempotency**: 
    - Introduced `Session::save_init` which resets the version to `1` and forces a write, allowing `orch init` to be used for recovery/reset without manual file deletion.
- **Test Integrity**: 
    - Fixed existing tests that used `get_envs()` on `tokio::process::Command` (which doesn't exist).
    - Added `test_reproduce_bug_report_parsing_failure` to verify the fix against the exact reported failure case.

## 4. Impact
- **Version Bump**: Released as **v1.7.0**.
- **System Stability**: The orchestrator is now resilient to schema changes and supports robust re-initialization.

## 5. Lessons Learned
- Always use `#[serde(default)]` for fields that might be added in future versions of a local state file.
- `std::process::Command` and `tokio::process::Command` have subtle API differences; ensure tests reflect the correct crate usage.
- Initialization commands must be idempotent to allow easy recovery from corrupted state.
